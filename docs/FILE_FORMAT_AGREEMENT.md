# 📄 اتفاقية تنسيق الملفات (File Format Agreement)

هذا المستند يوثّق **تنسيق كل ملفات البيانات** في المشروع، لضمان التوافق التام بين دوال الحفظ (`save*`) ودوال التحميل (`load*`).

> ⚠️ **هام جداً:** أي تعديل على تنسيق الملفات يتطلب تحديث كل من: دوال الحفظ، دوال التحميل، وهذا المستند، وإلا سيحدث خلل في قراءة البيانات.

## 📂 مجلد `data/`

كل ملفات البيانات تُحفظ في مجلد `data/`، **ويُنشأ تلقائياً** عند أول تشغيل للبرنامج (عبر دالة `ensureDataDirectory`).

**الملفات:**
- `halls.txt` — بيانات الصالات (يُرفع إلى Git كبيانات تجريبية).
- `movies.txt` — بيانات الأفلام والمقاعد (يُرفع إلى Git كبيانات تجريبية).
- `bookings.txt` — بيانات الحجوزات (مستثنى من Git لأنه يتغير مع كل عملية حجز).
- `admin.hash` — بصمة كلمة سر المدير المشفرة بـ SHA-256 (محلي فقط، **لا يُرفع إلى Git أبداً** لأسباب أمنية).

---

## 🏛️ ملف `halls.txt`

**الغرض:** تخزين بيانات كل الصالات.

**التنسيق:** كل صالة في **سطر واحد**، الحقول مفصولة بـ `|` (Pipe).

**الحقول بالترتيب:**
1. `hallId` (int) — رقم الصالة.
2. `name` (string) — اسم الصالة.
3. `rows` (int) — عدد الصفوف.
4. `cols` (int) — عدد الأعمدة (المقاعد في كل صف).
5. `isVip` (int 0/1) — هل الصالة VIP؟ (0 = لا، 1 = نعم).

**مثال:**
```text
1|Main Hall|5|6|0
2|VIP Hall|4|5|1
```

**الدوال المسؤولة:** `saveHallsToFile`، `loadHallsFromFile`.

---

## 🎬 ملف `movies.txt`

**الغرض:** تخزين بيانات الأفلام مع خريطة المقاعد الخاصة بكل فيلم.

**التنسيق:** لكل فيلم **3 أجزاء** بالترتيب:
1. **سطر بيانات الفيلم** (7 حقول مفصولة بـ `|`).
2. **سطر أبعاد المقاعد** (`rows|cols`).
3. **صفوف المقاعد** (كل صف في سطر منفصل، وطول السطر يساوي عدد الأعمدة `cols`).

**حقول الفيلم بالترتيب:**
1. `movieId` (int)
2. `name` (string)
3. `genre` (string)
4. `showtime` (string)
5. `price` (double) — يُحفظ بخانتين عشريتين.
6. `hallId` (int)
7. `status` (string) — `Now Showing` / `Coming Soon` / `Ended`.

**رموز المقاعد:**
- `O` = مقعد فارغ (Available).
- `X` = مقعد محجوز (Booked).

**مثال:**
```text
1|Action movie|action|7:00 PM|100.00|1|Now Showing
5|6
XOOOOO
OOOOOO
OOOOOO
XOOOOO
OOOOOO
```

**الدوال المسؤولة:** `saveMoviesToFile`، `loadMoviesFromFile`.

## 🎫 ملف `bookings.txt`

**الغرض:** تخزين تفاصيل الحجز + بيانات العميل + المقاعد المحجوزة + تاريخ الحجز.

**التنسيق:** لكل حجز **4 أجزاء** بالترتيب:
1. **سطر بيانات الحجز** (10 حقول مفصولة بـ `|`).
2. **سطر بيانات العميل** (3 حقول مفصولة بـ `|`).
3. **أسطر المقاعد** (كل سطر يحتوي على `row col` مفصولين بمسافة) — عدد الأسطر يساوي `seatCount`.
4. **سطر التاريخ** (`day month year` مفصولين بمسافة).

**حقول الحجز بالترتيب:**
1. `bookingId` (int)
2. `movieId` (int)
3. `movieName` (string)
4. `seatCount` (int)
5. `pricePerSeat` (double)
6. `originalPrice` (double)
7. `discountAmount` (double)
8. `totalPrice` (double)
9. `isActive` (int 0/1) — 1 = نشط، 0 = ملغي.
10. `isPaid` (int 0/1) — 1 = مدفوع، 0 = غير مدفوع.

**حقول العميل بالترتيب:**
1. `customerId` (int)
2. `customerName` (string)
3. `phone` (string)

**مثال (حجز مقعدين في الصف الأول):**
```text
1|1|Action movie|2|100.00|200.00|0.00|200.00|1|1
501|Ahmed Mohamed|01034168403
0 0
0 1
3 9 2026
```

**الدوال المسؤولة:** `saveBookingsToFile`، `loadBookingsFromFile`.

## 🧾 مجلد `receipts/`

**الغرض:** حفظ التذاكر التي يتم تصديرها كملفات نصية للعميل.

**اسم الملف:** `Ticket_[bookingId].txt` (مثال: `Ticket_1.txt`).

**الدالة المسؤولة:** `exportTicketToFile`.

**ملاحظة:** هذا المجلد **مستثنى** من Git.

## ⚠️ ملاحظات عامة وقواعد صارمة

1. **الفاصل (Delimiter):** كل الحقول مفصولة بـ `|` (Pipe) **بدون أي مسافات** قبل أو بعد الفاصل.
2. **النهايات:** الملفات تُحفظ بنهاية سطر Unix (`\n`). الكود يدعم أيضاً قراءة ملفات Windows (`\r\n`) عبر دالة `readLine` في `fileUtils`.
3. **الترميز:** كل الملفات تُحفظ بترميز **UTF-8**.
4. **الأسعار:** تُحفظ دائماً بخانتين عشريتين (مثال: `100.00`) لضمان عدم فقدان الدقة عند الحساب.
5. **التحقق (Validation):** دوال التحميل (`load*`) مصممة لعدم انهيار البرنامج (Crash). إذا وجدت سطراً تالفاً أو ناقصاً، تتخطاه وتطبع تحذيراً (Warning).
6. **الأمان (منع الحقن):** **ممنوع تماماً** استخدام الرمز `|` داخل أسماء الأفلام أو أسماء العملاء، لأن ذلك سيعطل قراءة الملف. (دالة `getStringInput` تمنع هذا تلقائياً).
